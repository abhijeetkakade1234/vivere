# Vivere PRD

## Product Summary

Vivere is a PWA for planning experiences instead of isolated purchases.

The user starts with a moment:

- first date
- birthday
- movie night
- rainy evening

Vivere turns that intent into a structured plan with timing, venue ideas, add-ons, and clear next steps.

## Problem

People do not struggle to buy. They struggle to plan.

Current commerce products assume the user already knows what they want. In reality, users usually know the occasion first and only discover the right purchases after that.

Typical planning friction:

- deciding where to start
- juggling timing and budget
- remembering add-ons like flowers, gifts, dessert, or reservations
- switching between products that each solve only one slice

## Product Thesis

If Vivere starts from the moment instead of the item, the product can remove decision fatigue and make the user feel like the evening or event is already handled.

The emotional goal is simple:

> “I didn’t have to think about every little thing.”

## Target User

The first target user is someone planning a small meaningful experience quickly on mobile.

Traits:

- time-constrained
- not looking for a long planning session
- wants confidence more than maximum optionality
- is comfortable approving a guided recommendation

## Core Product Principles

1. Start with the occasion, not the SKU.
2. Ask one decision at a time.
3. Make the UI calm, not dashboard-like.
4. Show rationale, not just results.
5. Keep execution reviewable before real actions happen.

## MVP Focus

The MVP should prove one thing well:

- a user can describe a moment
- answer a short intake
- get a coherent plan in under a minute

The first flow does not need to prove every category, every occasion, or deep personalization.

## Frontend Goals

- feel premium, calm, and guided
- keep the planning flow mobile-first
- make the returned plan easy to scan and trust
- keep AI invisible behind structured UI
- preserve a clear path from “what’s happening today?” to “here’s your plan”

## Success Criteria

- the user understands the product in under 10 seconds
- the intake feels short enough to finish
- the returned plan feels thoughtful, not generic
- the user can tell what the next action is without confusion

## Non-Goals

- chatbot-first UX
- dashboard-heavy navigation
- exposing provider complexity in the UI
- turning the frontend into a second backend
